## 2. Pedigree DOM

Observed pet URL: `https://ovipets.com/#!/?src=pets&sub=profile&usr=4973830&pet=155812382`

Selectors:

```css
section#pedigree
section#pedigree fieldset.ancestors table
section#pedigree fieldset.ancestors a.pet[href*="pet="]
```

Container heading is exactly `Pedigree`. Child groups are `fieldset.daughters`, `fieldset.sons`, and `fieldset.ancestors`.

The observed ancestor table has three `<tr>` rows. They represent parents, grandparents, and great-grandparents, so "shares a visible ancestor" should mean up to three visible ancestor generations. Empty slots are literal `<td>&nbsp;</td>` cells.

The game did not display a relationship warning in the ordinary breeding confirmation tested. A real related-pair attempt was not made. The extension should still compare IDs from `fieldset.ancestors` itself and treat the game's own behavior as unconfirmed.

Each card is an `<li>` containing `input[name="PetID[]"]`, an `a.pet[href*="pet="]` image link (with `usr=` and `pet=` in its href), and `a.pet.name`. Cooldown is exactly `img[src*="/heart_iceblue.png"]` inside `.right`; its `title` attribute reads e.g. "2 days left until she can breed again". A card with no such image can currently breed.

The observed enclosure rendered 51 cards at once with no pagination/Load More/infinite-scroll control. Note: "Enclosures themselves are jQuery UI tabs and an unselected enclosure may be loaded when its tab is opened; scan every enclosure tab rather than only the first one" — the exact enclosure-tab-bar markup itself was not captured, so multi-enclosure accounts currently require manually switching tabs and re-running the scan for each one.

## 6b. Pet tab bar

Tabs are `<li role="tab">` elements inside `<ul role="tablist">`; the clickable element is the `<a class="ui-tabs-anchor">` inside, whose `<span>` holds the exact tab label ("Overview", "Pedigree", "Breeding", "Lab", "Edit"). `location.hash` does **not** change when switching tabs; content loads into the tab's panel in place. Breeding candidates appeared after ~505ms with no visible loading spinner in this run — wait for the actual DOM (`section#breeding` plus at least one candidate anchor), not a fixed sleep.

## Implementation corrections applied

1. Use the current 47-color Help list instead of the old guessed 14-color constant.
2. Find tabs by their `<span>` text or `panel` attribute; never depend on `location.hash` changing.
3. Parse pet IDs from `a.pet[href*="pet="]` or `input[name="PetID[]"]`; never parse the generated `<li id>` (its prefix changes).
4. Detect breeding cooldown only by the ice-blue heart image, not generic heart text.
5. Scope modal controls (`Ok`/`Cancel`) to the visible dialog; the text is generic and reused across workflows.
6. Pedigree traversal targets `section#pedigree fieldset.ancestors` specifically, so daughter/son IDs are never mistaken for ancestors.
7. Use `tr#Body`, `tr#Scales`, `tr#Extra` by id; there is no Eyes row to read.
8. Wait for the actual target DOM rather than fixed sub-second sleeps alone.

## Species verification handoff — v4.10.0

The direct `pet_turn_egg` command can leave a Name the Species dialog inside an inactive
Daily Maintenance or Hatchery worker tab. v4.10.0 detects the visible dialog, activates
that exact tab/window, plays a local three-note alert, and waits for the user's answer.
The answer is committed to `owehSpeciesMemory` only after the game completes the pending
Turn Egg command. The queue then resumes without restarting.
